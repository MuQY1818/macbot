# 加速

[English](acceleration.md)

默认后端是 Apple GPU（MPS）上的 PyTorch。部分策略在 macbot 里还有 MLX 后端：它读取同一个 LeRobot 权重，使用权重自带的分词器和处理器，通常更快。本页介绍怎么用 MLX、一个后端要通过哪些检查 `auto` 才会选它，以及[支持一览](policies.zh.md#支持一览)里每一行背后的测量数据。

## 使用 MLX

在 Apple 芯片的 Mac 上安装附加依赖，然后在你的权重上对比两个后端：

```bash
pip install 'macbot[mlx]'
CKPT=path/to/pretrained_model
macbot --config robot.yaml bench --policy "$CKPT" --backend torch -n 30
macbot --config robot.yaml bench --policy "$CKPT" --backend mlx -n 30
```

`bench` 输入的是空白图像，不会打开相机或机械臂。`--profile` 会另外跑一遍、分阶段计时，所以各阶段加起来不等于端到端时间。`--no-compile` 关闭图编译。

部署时给 `macbot run` 加 `--backend auto` 或 `--backend mlx`，或者在配置里写 `policy: {backend: auto}`。

- `--backend auto` 只在支持一览列出的架构和模式下用 MLX，并打印让它通过验证的权重；否则打印一行说明为什么留在 PyTorch。
- `--backend mlx` 只要这个策略有 MLX 实现就用 MLX，不管有没有通过验证。
- 用 MLX 时，`--mode auto` 以不加引导的异步方式执行动作块；`--mode rtc` 在 MLX 上为 π0 和 π0.5 执行带引导的 RTC。

安装 MLX 不会改变默认后端和默认执行模式。

## "无损"是什么意思

一个更快的后端，在权重、观测和初始噪声都相同时，必须给出和参照相同的动作。我们比较的是后处理之后的动作：机械臂关节用角度，夹爪用权重自己的单位，报告平均值和第 99 百分位。

- 对 ACT 这种确定性策略，关节误差的两项统计都要在 0.01° 以内，夹爪误差在量程的 0.1% 以内。
- 对需要采样噪声的策略，误差还要小于两次换种子的参照运行之间的差异。
- 对 π0 和 π0.5，参照是一次 float32 运行。MLX 必须更快，并且要么满足上面的绝对限值，要么至少和 macbot 部署的 bf16 PyTorch 一样接近 float32。

在这些帧上对得上，不代表每一次实际运行都相同。这些对比也都没有测量机械臂上的任务成功率。

## `auto` 怎么决定

`auto` 会检查策略类型、保存的处理器格式、执行模式、编译设置，以及 MLX 是否已安装。只有这些都和某个在公开或录制权重上通过了上述对比的配置一致，它才会选 MLX。它不检查机器型号，所以这里的耗时只说明 M5 Pro 上的情况。

## 更快但有损的选项

这些选项用精度换速度，使用前请在你自己的权重上检查。

| 选项 | 作用 |
|---|---|
| `--steps N` | 减少 π0.5 的去噪步数；π0 只在 MLX 上可用。 |
| `--mlx-time-grid quadratic` | 把去噪步集中在接近干净动作的一端。步数相同时比均匀步长好。 |
| `--mlx-bits 8` 或 `4`，配合 `--mlx-quantize prefix`、`expert` 或 `both` | 量化权重。8 位省了显存但更慢；4 位让误差大幅增加。 |
| `--torch-autocast fp16` 或 `bf16` | ACT 和 Diffusion 在 MPS 上用更低精度。 |

另外两个 PyTorch MPS 实验选项只改变运行方式、不改变精度：`--torch-channels-last` 改变 Conv2d 权重的内存布局，`--torch-single-readback` 去掉 ACT 里一次多余的设备同步。`--torch-compile` 是编译 Diffusion 去噪网络的实验选项；ACT 的编译被关掉了，因为测试用的 MPS 版本生成不了它的 Metal 内核。`auto` 不会打开这些选项中的任何一个。

## 测量数据

除非某一节另有说明，测试环境都是：Mac17,9（Apple M5 Pro，20 核 GPU，48 GiB），macOS 27.0.1，MLX 0.32.4，LeRobot 0.7.0；同一时间只跑一个测试进程，至少预热 5 次、计时 50 次。计时从观测开始，到动作回到 CPU 为止。误差都写成平均值 / p99。

## 复现

离线工具在源码目录的 `tools/accel` 下，需要 LeRobot 0.7.0 环境，不会打开相机或机械臂。观测存档和中间轨迹请放在仓库之外。

```bash
python -m tools.accel.recorded_observations --help   # 从数据集里抽取帧
python -m tools.accel.compare_backend --help         # 在这些帧上计时并对比各后端的动作
python -m tools.accel.eval_fidelity --help           # π0.5 对照参照的保真测试
python -m tools.accel.bench_mlx --help               # π0.5 分阶段的 MLX 测速
```

`compare_backend --pi-fp32` 为 π0 和 π0.5 准备 float32 的 PyTorch 参照；`--save-rtc-leftovers` 和 `--rtc-leftovers` 让不同后端共用同一段 RTC 历史。`--act-mlx-tf32` 和 `--act-mlx-fp16` 用来复现 ACT 的有损那几行。
